# Research topic classifier: dataset, labels and evaluation protocol

Component 3, module 5 (Research Trend Analysis). This document describes how the
training data is obtained and labelled, and how the model is evaluated. Every
number reported for the model comes from files generated by the scripts below.
None are written by hand.

## 1. Source

- **Dataset:** Cornell University, *arXiv Dataset* on Kaggle:
  <https://www.kaggle.com/datasets/Cornell-University/arxiv>
- **File used:** `arxiv-metadata-oai-snapshot.json`. It is a JSON-lines file with
  one record per paper and the fields `id`, `title`, `abstract`, `categories`,
  `versions`, and others. Only metadata is used; no PDFs.
- **Licence:** the metadata is released by arXiv under CC0. Each paper keeps
  its own licence.
- The snapshot is updated regularly. The exact file used is identified by its
  SHA-256 hash, which `data/processed/manifest.json` records along with its size
  and record count.

### How to obtain it

Option A, browser:
1. Sign in to Kaggle and open the dataset page.
2. Click **Download**.
3. Unzip the archive. It is about 1.5 GB zipped and about 4.5 GB unzipped.
4. Put `arxiv-metadata-oai-snapshot.json` in `ml-service/data/raw/`.

Option B, Kaggle CLI (needs an API token in `%USERPROFILE%\.kaggle\kaggle.json`):

```powershell
pip install kaggle
kaggle datasets download -d Cornell-University/arxiv -p data/raw --unzip
```

`data/` and `models/` are git-ignored. The raw file is never committed.

## 2. Category selection (first run)

| Category | Area |
|---|---|
| `cs.CV` | Computer Vision and Pattern Recognition |
| `cs.CL` | Computation and Language (NLP) |
| `cs.CR` | Cryptography and Security |
| `cs.RO` | Robotics |
| `cs.DB` | Databases |

These five were chosen for these reasons:
- Each is a well-defined research area that is relevant to undergraduate projects.
- Each has enough papers per year.
- Their topics overlap only partly. This makes them a fair first test of whether
  the text separates research areas.

`cs.LG` (Machine Learning) and `cs.AI` (Artificial Intelligence) are left out
of the first run **on purpose**. They are broad categories that many papers
from other areas are cross-listed into, so their labels are much noisier. They
will be added when coverage is expanded. The category list is a command-line
option, so expanding it needs no code changes.

## 3. Label policy

- **Label = primary category = the first entry of the `categories` field.**
  arXiv lists the primary category first. This is the convention used by the
  OAI metadata. We treat it as an assumption and do not verify it per paper.
- A paper is kept only if its primary category is one of the selected ones.
- Cross-listed papers are kept and labelled by their primary category, for example
  `cs.CV cs.LG` → `cs.CV`. This is the realistic setting. The manifest reports
  two shares:
  - `cross_listed_share`: papers listed in any second category;
  - `cross_listed_within_selected_share`: papers also listed in another of the
    five selected categories. These are the ambiguous cases.

## 4. Filters

| Filter | Rule |
|---|---|
| Time window | First version (`versions[0].created`) submitted in 2018–2024 inclusive |
| Missing date | Dropped |
| Abstract length | Fewer than 30 words is dropped. This removes most "paper withdrawn" notices. |
| Duplicate id | Only the first record is kept |
| Duplicate title | If the same normalised title appears under more than one id, **all** copies are dropped, so one paper can never be in both train and test |

**Text cleaning** is in `ml/text_utils.py` and is shared with the future API:
- whitespace is collapsed;
- LaTeX maths between `$...$` is removed;
- arXiv category codes such as `cs.CV` are removed, so the label cannot leak
  into the input.

The model input is `title + " " + abstract`.

## 5. Reproducible sampling

- Each eligible paper gets the key `sha256("<seed>:<arxiv id>")`. For each
  category, the **N papers with the smallest keys** are selected.
- First run: N = 2,000 and seed = 42, so 10,000 papers in total.
- The selection depends only on the snapshot contents and the seed. It does not
  depend on file order or on Python's random state. Running the script again on
  the same file gives a byte-identical sample, which you can check with
  `sample.content_sha256` in the manifest.
- If a category has fewer than N eligible papers, all of them are used. The
  shortfall is reported in the manifest (`categories_below_target`).

## 6. Evaluation protocol (`ml/train_classifier.py`)

1. **Split first.**
   - The data is split into train and test with a stratified 80/20 split
     (`train_test_split`, seed 42).
   - The split happens before any model or vectorizer is fitted.
   - The script checks that train and test share no id and no normalised title.
     It stops if the check fails.
   - The test ids are saved to `reports/<run>/test_ids.txt`.
2. **No test-set information in training.**
   - TF-IDF is a step inside the sklearn `Pipeline`. During cross-validation it
     is fitted on the training folds only, and for the final model on the
     training set only.
3. **Model selection on train only.**
   - The parameters are chosen by 5-fold stratified cross-validation on the
     training set, using macro-F1 as the score.
   - Linear SVM: `C ∈ {0.1, 0.5, 1, 2}`.
   - The best setting is refitted on the full training set.
4. **One look at the test set.**
   - Each model scores the test set once.
   - Reported metrics:
     - accuracy;
     - precision, recall and F1, macro-averaged and weighted;
     - precision, recall, F1 and support for each category;
     - the confusion matrix.
5. **Baselines under the same protocol.**
   - Majority class (`DummyClassifier`).
   - TF-IDF + Multinomial Naive Bayes (`alpha` tuned by the same cross-validation).
   - The results are reported exactly as they come out. The SVM is not assumed
     to win.

TF-IDF settings:
- word unigrams and bigrams;
- `min_df=2`;
- sublinear TF;
- English stop words;
- accents stripped.

The classes are balanced by construction, so no class weighting is used.

## 7. Reproduce

```powershell
cd ml-service
.\.venv\Scripts\Activate.ps1
python -m ml.prepare_data --input data/raw/arxiv-metadata-oai-snapshot.json `
    --categories cs.CV cs.CL cs.CR cs.RO cs.DB --per-category 2000 --years 2018-2024 --seed 42
python -m ml.train_classifier --data data/processed/sample.jsonl.gz --seed 42
```

## 8. Known limitations

- The labels are author-chosen primary categories. They are not expert
  annotations, and some papers truly belong to two areas.
- A random split measures performance on papers from the same period as the
  training data. A time-based split (train on earlier years, test on later
  years) is planned as a further check.
- Five categories are a first step. Accuracy usually drops as more and closer
  categories are added, for example `cs.LG` and `cs.AI`.
